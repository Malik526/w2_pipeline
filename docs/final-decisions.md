# Final Decision Log

Concise reference for every major design decision in this system, with a
pointer to the evidence behind it. Full reasoning for each lives in the
cited phase/artifact; this table is meant to be usable standalone (e.g.
in an interview) without re-reading every experiment doc.

| # | Decision | Selected | Rejected alternative | Evidence / reason | Reference |
|---|---|---|---|---|---|
| 1 | Extraction output shape | A typed, `extra="forbid"` Pydantic `W2Document` canonical schema | A loose dict/JSON blob | Schema violations fail loudly at the boundary instead of silently propagating; every downstream stage (validation, review, export) can trust the shape without re-checking it | `docs/contracts/canonical-w2-schema.md` |
| 2 | Primary extraction architecture | Pipeline A: OCR + deterministic rule-based parser | Pipeline B: generative VLM (Qwen3-VL-4B-Instruct) as primary | VLM reached 100% only on the 80% of documents that didn't fail outright, at 58-70s/doc vs. 1.2-1.4s/doc and far higher GPU cost, for a document type OCR already handles well | Phase 5A, ADR Sections 2-4 |
| 3 | Production OCR backend | PaddleOCR (GPU) | Tesseract (CPU) as primary | PaddleOCR GPU reached 100.0%/100.0% (clean/worst-condition) at 1.2-1.4s/doc vs. Tesseract's 99.3%/67.7% at 2.3s/doc on the same 150-doc benchmark; Tesseract retained as a documented cost-optimized CPU alternative, not removed | Phase 8B, `phase8c2_final_paddleocr_gpu_all_variants_600.json` |
| 4 | Dual-engine OCR voting | Not implemented | Running both engines and reconciling disagreements | No evidence of complementary error patterns was ever established, and it doubles OCR cost/latency for an unproven benefit; PaddleOCR alone already reached 100% on the clean benchmark | Phase 8B; ADR Section 6 |
| 5 | Rotation handling | Anchor-relative detection (checkbox) + accepting residual OCR-layout limits elsewhere | A global pre-OCR deskew/rotation-correction step | Phase 8C.9's conditional small-angle scan-deskew experiment was net harmful overall (regressed more documents than it fixed) -- fixed-ratio-zone calibration is canvas-geometry-specific, not purely rotation-specific, so "straightening the image" doesn't transfer cleanly to zone-based parsing | Phase 8C.9 (`phase8c9-conditional-scan-deskew.md`) |
| 6 | Box 13 (`retirement_plan`) checkbox detection | Anchor-relative pixel/CV detector (locates the checkbox relative to its printed label, not a fixed image-coordinate zone), promoted to the default | The original fixed-zone pixel detector as the sole mechanism | Fixed-zone detection silently failed under rotation (the checkbox physically moves in the fixed coordinate frame); anchor-relative detection tracks the label instead of absolute pixels, closing the rotation gap without depending on OCR text (PaddleOCR's text detector never perceives the checkbox glyph as text at all) | Phase 8C.10 (measurement) -> 8C.11 (promotion), `phase8c11-anchor-checkbox-promotion.md` |
| 7 | Global OCR-confidence-based validation routing | Not implemented | Using PaddleOCR's/Tesseract's native per-token confidence as a validation signal | Phase 8C.4 measured native PaddleOCR confidence against known-correct vs. known-wrong fields and found it uninformative for this document type/failure pattern; Tesseract and PaddleOCR also have no comparable confidence semantics, so a unified score would misrepresent both engines | Phase 8C.4 (`phase8c4-paddle-native-confidence-analysis.md`) |
| 8 | `employer.name` validation | Evidence-based signals (address-leak heuristic + layout-span anomaly, combined) promoted into the production validator | Trusting the extracted value with no dedicated check | A real, benchmark-invisible extraction gap (employer name occasionally absorbing part of the address line) was caught only because production validation checked something a pure field-accuracy benchmark never would; measured, combined signal promoted after confirming zero false-review cost | Phase 8C.5-8C.8 |
| 9 | Box 13 checkbox validation | Dedicated evidence-based rule (`retirement_plan_checkbox_evidence`) judging the *detector's evidence quality*, not the extracted boolean's plausibility | Leaving checkbox correctness entirely to extraction accuracy | A boolean is structurally valid even when wrong -- this is exactly why the pre-8C.12 validator silently accepted all 60 Phase 8C.2 checkbox errors; the rule is symmetric (`True`/`False` judged identically) | Phase 8C.12 (`phase8c12-checkbox-validator.md`) |
| 10 | `employer.address`/`employee.address` validation | Evidence-based rule (`address_extraction_evidence`) that distinguishes "OCR found text here but couldn't assemble it" from "genuinely no address printed" | A bare `if address is null` null-check | `usable_row_count` sits exactly at the expected line count for every correct extraction and strictly below it for every structurally-failed one, zero exceptions across 600 documents -- a clean, measured separator, not an assumed one; closed unsafe acceptance 2.17% -> 0.33% overall, 7.33% -> 0.0% on `rotated_png`, with zero added false-review cost | Phase 8D.1B (`phase8d1b-address-safety-and-box12-slot-semantics.md`) |
| 11 | Box 12 canonical representation | Semantic coded entries only (`{code, amount}` pairs); blank-code placeholder slots are omitted, a nonzero amount with no code routes to review | Representing every visually rendered 12a-12d slot, including blank ones, as a canonical entry | Per the 2026 IRS W-2 instructions, Box 12 represents coded items, not print-layout slots; an airtight 600-slot audit found a blank code's amount is always blank/`$0.00` (0 exceptions) and a populated code's amount is always nonzero (0 exceptions), confirming the existing omission was already correct, not an oversight | Phase 8D.1B; `Box12Entry` docstring, `box_12_amount_without_code` rule |
| 12 | Human review before finalization | Mandatory: `finalize_document` raises `NotAcceptedError` for any non-`accepted` status; a `needs_review` document can only reach output via review -> correction -> revalidation -> `accepted` | Allowing an operator to force-export a `needs_review` document | A validation status exists specifically to gate untrustworthy output; an override path would silently defeat every evidence-based rule built to justify it. Proven blocked-then-unblocked end to end in Phase 8D.2 | `src/w2_pipeline/downstream/finalize.py`; Phase 8D.2 |
| 13 | Review correction mechanism | Explicit, human-supplied field/value pairs via a generic dotted/indexed field-path (no field allowlist, no AI auto-correction) | An LLM-suggested or auto-inferred correction | Corrections must be attributable to a human decision, not a model's guess, for a system whose entire premise is "catch what automation got wrong" | Phase 7 (`phase7-review-workflow.md`); `docs/contracts/review-and-downstream-output.md` |
| 14 | Downstream output determinism | `export_json`/`export_csv` produce byte-identical output for byte-identical input, verified by direct re-export comparison | Any non-deterministic serialization (e.g. dict ordering, timestamps in output) | Downstream tax-prep consumers need reproducible output for the same accepted document; verified explicitly in Phase 8D.1 and re-verified in Phase 8D.2 | Phase 8D.1 (`phase8d1-downstream-json-csv-verification.md`); Phase 8D.2 |
| 15 | Frontend / GUI | Not built | A review web UI on top of `ReviewRecord`/`review.cli` | Out of scope for this take-home; the backend workflow is independently complete and provable via CLI alone (Phase 8D.2's operator walkthrough) | `docs/known-limitations.md` #8 |
| 16 | Benchmark data source | Synthetic Symage dataset (`Symage/synthetic-us-forms-preview`) | A real taxpayer W-2 corpus | No real taxpayer data is available or appropriate for a take-home project; synthetic data lets every number in this project be freely shared and reproduced, at the explicit cost of not being a real-world accuracy claim | `docs/known-limitations.md` #1; every `docs/experiments/*.md` |

See `docs/final-evaluation-summary.md` for the numbers behind rows 2, 3,
9, 10, 11, and 16, and `docs/known-limitations.md` for what each decision
still leaves open.
